# GUI 4-Software Transfer Tasks: LibreCAD -> FreeCAD -> KiCad -> Blender

Owner: taozhuo

This dataset contains 10 category-3 multi-software transfer tasks. All four tools are GUI applications from the allowed software list. The tasks intentionally vary product domain, geometry, electronics content, and Blender visualization target while keeping the same evaluable open-format chain.

Evaluator surface per task: stage1 DXF, stage2 STL/handoff DXF, stage3 KiCad native board file plus KiCad-exported SVG profile, and stage4 Blender GLB. The checked-in stage4 GLBs are real Blender GUI exports from the remote validation instance downloaded back into each task's `ground_truth` directory.

## Evaluator Dependencies

The VM evaluator environment is expected to already contain `ezdxf`, `trimesh`, `pygltflib`, and `numpy`; the task configs upload seed files but do not install packages. The eval scripts use these packages directly: `ezdxf` for DXF, `trimesh` for STL, `pygltflib` for GLB, and `numpy` for numeric bounding-box checks. The SVG profile check uses Python's standard XML parser.
## Initial Files

Each task has an `init_file/seed_*.dxf` generated by `generate_assets.py` with `ezdxf`. The task config uploads that seed to `/home/user/Desktop/`; the LibreCAD stage must edit it into the required `stage1_*.dxf` and remove the seed `GUIDE` construction layer.

## Strong Transfer Checks

The tasks enforce a four-stage dependency chain: LibreCAD creates `stage1_*.dxf`; FreeCAD must consume it and export both `stage2_*.stl` and `stage2_*_handoff_outline.dxf`; KiCad must import that handoff as `Edge.Cuts`, save a native `stage3_*_board.kicad_pcb`, and export a Blender-friendly `stage3_*_board_profile.svg`; Blender must consume the stage-2 STL and stage-3 SVG profile and export `stage4_*.glb`. The eval scripts check intermediate existence, file formats, geometry agreement across handoffs, and Blender GUI-export evidence showing the imported stage-2 STL object name and imported stage-3 SVG filename are present in the GLB. The SVG file itself is separately checked for the `EDGE_FROM_STAGE2_HANDOFF` handoff marker.

## Intermediate Outputs

Each `flow_spec.json` has an explicit `intermediate_outputs` array. The eval scripts first verify this manifest and then validate every intermediate artifact: LibreCAD `stage1_*.dxf`, FreeCAD `stage2_*.stl`, FreeCAD-to-KiCad `stage2_*_handoff_outline.dxf`, KiCad native `stage3_*_board.kicad_pcb`, and KiCad-to-Blender `stage3_*_board_profile.svg`. The final GLB is checked separately for evidence that Blender imported the FreeCAD STL and the KiCad SVG profile through the GUI.
